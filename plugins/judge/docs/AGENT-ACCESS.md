# Optional agent access

Judge registers one tool, `judge_ask`, with a plain JSON Schema for provider compatibility. Runtime validation reuses the strict CLI/RPC ask and run schemas, removing caller identity and the ad hoc public declaration. JSON depth, losslessness, reserved map keys and byte limits are checked before any source/provider work. Exactly one of `ask` and `run` is required. The execution context supplies thread/project attribution.

`enableAgentTool` is a native BB boolean setting with default `false`. The agent configurator selects neither the tool nor the `judge` skill while disabled. Enabling does not perform inference, alter model configuration or invalidate calibration. Configure selection uses a current in-memory setting; execution refreshes BB settings to refuse stale selections even after a missed notification. Access transitions invalidate reads already in flight, so a delayed enabled result cannot undo revocation or revive work after disable/re-enable. Already selected agent sessions can call only while the setting remains enabled. Disabling aborts active tool calls, and disposal prevents delayed readiness reads from restarting work. The host owns registration/listener cleanup.

Ad hoc state is always sensitive through the tool. Saved-set overrides preserve source privacy. Both branches use the existing model/fallback policy, deadlines, cache, persistence and cancellation semantics. The tool cannot save definitions/models, change secrets/defaults/private policy, accept calibration, enable bindings or run arbitrary RPC actions. CLI/RPC availability does not depend on this tool setting. BB plugins are full-trust server code; this workflow setting is not a human-versus-agent security boundary for other public CLI/RPC management methods.

Output is JSON text capped at 64 KiB UTF-8. A fitting result contains `{kind:"verdict",verdict:...}`. Otherwise `{kind:"summary",answersOmitted:true,verdict:...}` preserves the run header, final outcomes and step status/model/timing/cache diagnostics, omitting whole answers and provenance. Consumers must not treat omitted answers as false or infer an answer from status. Full persisted details use the existing `runs.get` RPC with the run ID; CLI `log` contains summaries only. Provider failures retain typed unavailable results, while boundary/operational errors return a sanitized error code.

The shipped skill documents narrow questions, named state, explicit no-match choices, yes-means-violation questions, authored cases and separate explicit calibration acceptance. It describes BB-native secret entry without collecting credentials. Offline tests execute every shell example with actual registered `--help`, validate both tool examples and parse the YAML case fixture. Other tests cover default/exclusive selection, unchanged model/default policy, malformed/oversized input refusal before dispatch, sensitive input, caller attribution, cancellation/revocation, missed notifications, disposal, whole-run budget and oversized-answer output. Live agent-provider selection remains a BBP-23 verification gate.

The final bounded live diagnostic verified native selection ON before a parent-coordinated stop/resume of the same owner, with a detached restoration fallback. The refreshed session exposed the Judge skill but no callable `judge_ask`; no invocation or substitute inference occurred. The flag was restored OFF and freshly verified before cancelling the fallback. This is a bounded client/session exposure gap, not a missing-credential result or a proven platform root cause. Native live invocation remains unverified; see [diagnostic limits and cleanup](LIVE-VERIFICATION.md#native-tool-exposure-diagnostic).
