# Compatibility review

Reviewed 2026-11-10 against the installed BB CLI 0.49.0, its generated scaffold, public SDK 0.6.132 declarations, and the installed BB plugin-authoring reference. No BB core changes are needed for the proposed read/record workflow. This is contract inspection, not a live inference or trigger test.

## Corrections to the supplied proposal

| Area                  | Evidence and decision                                                                                                                                                                                                                                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SDK version           | `bb plugin new judge` generated SDK 0.6.132 and BB `>=0.49`. Pin the package to that checked baseline; the draft's 0.6.138 and core commit were not the installed baseline.                                                                                                                                                                |
| Location and identity | Scaffold generates `bb-plugin-judge/`; move to this repository's `plugins/judge/`. Package name `bb-plugin-judge` derives plugin ID `judge`; no separate manifest ID is needed.                                                                                                                                                            |
| Scaffold              | Generated app is a todo demo. Remove it, its skill, UI dependencies, and `bb.app`. Add frontend only when verdict UI is implemented.                                                                                                                                                                                                       |
| TypeSafe SDK          | The live [TypeSafeClientConfig reference](https://docs.typesafe.ai/sdk/javascript/api/interfaces/TypeSafeClientConfig) explicitly documents `baseURL` and `fetch`. The draft's contrary rationale is obsolete. Plain fetch remains the selected small transport implementation for shared deadlines and Workers AI envelope normalization. |
| Provider schema       | TypeSafe's [quickstart](https://docs.typesafe.ai/introduction/quickstart) and [score reference](https://docs.typesafe.ai/primitives/score) describe typed answers and fractional expected scores. Preserve the schema; do not coerce a score to an integer or interpret confidence as probability of correctness.                          |
| Workers AI            | The official [Clef page](https://developers.cloudflare.com/workers-ai/models/clef/) confirms model ID `@cf/cloudflare/clef`, body selector `clef` or `clef-flash`, 64 questions, and a 65,536-token context. Adapter implementation still needs recorded request/response fixtures and a credentialed smoke test.                          |
| Local servers         | A configurable URL does not prove that arbitrary Ollama or llama.cpp installations implement System One. Support only endpoints that actually pass the compatibility probe; do not advertise generic server support. A server-process `localhost` URL targets BB's server, not the thread's remote host.                                   |
| Model estimates       | Do not encode the draft's pricing, latency, or Jev version examples as defaults. Discover a supported version during connection setup. Clef aliases may change behind the name; calibration records must acknowledge that limitation.                                                                                                      |
| CLI host routing      | `PluginCliContext` has `cwd`, `threadId`, `projectId`, and `signal`, not `hostId`. Resolve thread → environment → host, or require `--machine` for file input without a thread. Never silently fall back to the server for caller-owned paths.                                                                                             |
| Metadata              | `getPluginMetadata` / `updatePluginMetadata` namespaces are not access-control boundaries. Other clients and plugins can write them. Store a small display summary, not full raw answers; use Judge's database for authoritative verdicts. Latest-per-set alone does not bound 256 KiB.                                                    |
| Trigger trust         | Caller `threadId` is useful attribution, not proof that a request is human. SDK RPC distinguishes plugin callers from clients, not humans from agents. Disabled-by-default triggers are a workflow guard, not an agent-proof security boundary.                                                                                            |
| Sidebar badge         | The row-metadata reference confirms two opt-ins, both off by default. Make the thread Info row the primary UI and row metadata an optional enhancement.                                                                                                                                                                                    |
| Completion example    | Commands and current changed files do not establish that checks ran after the last edit, or cover the current diff. Rename the outcome to missing observed check evidence. Exact revision verification is outside this spike.                                                                                                              |
| Data classification   | Titles, assistant text, prompts, command arguments, paths, goals, and failure messages can all disclose private information. Default these to sensitive, unlike the draft. Only known identifier-only event projections may be public.                                                                                                     |
| Token budget          | Character count is not token count. Bound serialized bytes and source sizes locally, include question text in accounting, and handle provider context rejection as `too_large`. Exact tokenizer accounting is a later adapter-specific capability.                                                                                         |

## BB integration map

The installed skill lives under BB's runtime skill directory. Its canonical source is the [BB plugin-authoring guide](https://github.com/get-bb/bb/tree/main/plugins/bb-guide/skills/bb-plugin-authoring). References below name files within its `references/` directory. Exact declarations are supplied by this package's pinned SDK; private bundled declaration filenames are inspection evidence, never import paths.

| Surface          | Checked contract                                                                                                                         | Implementation follow-up                                                                                                                                                                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Lifecycle        | `backend-events.md`; SDK `thread.idle` has `{ thread, lastAssistantText: string \| null }`; `turn.failed` has a distinct failure payload | Separate event adapters; never cast one payload to the other. Events are best effort, not a durable queue.                                                                                                                                                               |
| Assistant output | `backend-sdk.md`: `threads.output`, or idle payload                                                                                      | Preserve absence; do not reuse a stale previous reply when the latest turn has none.                                                                                                                                                                                     |
| User prompts     | SDK exposes `threads.promptHistory(ThreadPromptHistoryArgs)` returning prompt history; also `threads.timeline`                           | Pinned prompt history has no origin/cursor. Use bounded origin-tagged request events instead; exclude plugin/system/agent/cross-thread/retry content and reject ambiguous groups. See SOURCES.md.                                                                        |
| Commands         | `threads.events.list`, descending order and `beforeSeq`, `item/completed`                                                                | Filter command-execution items; retain exit status and sequence. Some providers emit different tool representations. Missing evidence is not proof that no check ran.                                                                                                    |

## Remaining validation gates

These do not block scaffold or schema work, but block claiming support for their respective features:

- Capture and validate both providers' complete request/response schemas, including optional usage, malformed answers, error envelopes, and model IDs. No credentialed inference was performed in preparation.
- Offline source contracts and representative idle fixtures now verify user-origin event filtering and goal clear replay. Live history retention, grouped-provider behavior, and end-to-end source/runner reads remain gates; unsupported evidence stays unavailable. See [source evidence](SOURCES.md).
- Verify file routing from an enrolled remote host and trigger disposal/reload with the live host.
- Calibrate examples against actual resolved model configurations. Example thresholds are not a calibration claim.
- Clef-flash's own model page now verifies its separate 24,576-token window and REST route; Clef has 65,536 tokens. Offline adapter fixtures and conservative caps are implemented; credentialed behavior and provider truncation limits remain unverified. See [transport evidence](TRANSPORTS.md).

AI Gateway, local hardware latency, arbitrary local-server compatibility, and the linked Claude background artifact were not needed for this scaffold and were not validated. They are not prerequisites or promises in the revised spike.
