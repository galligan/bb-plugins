## Small reviewable prototype

The first offline prototype adds **Bot settings** in the native thread composer through `app.composer.customize`, plus an owned identity/role entry in native Info and its context-card counterpart where the host already renders that card. It merged in PR161 as `09f7e4d` after independent review and CI, while coordinated runtime acceptance remains pending; no live support is inferred from registration or harness tests. Use existing keyed SQLite ownership reads and their invalidation tags, shared by the contributions. Do not add a producer merely to display records that Bots already invalidates on change. Render nothing while ownership is unknown or absent. No model control is removed and no selection/draft/lock/submit API is called on mount.

This directly tests native placement, per-pane ownership and settings access without changing execution. A separate explicit-selection experiment can later exercise `setSelection` in a safe fixture: preserve a draft plus attachment, change only a supported same-provider value, record the native settled selection, and verify no submit/queue/turn. Provider switching is excluded from that first live experiment because its documented handoff behavior changes the draft. Neither experiment adopts a permanent model-control policy.

Harness checks: owned versus foreign threads, scope changes and late ownership responses, retained draft/attachment and execution selection, no send/submit/lock/queue calls, mutation-driven metadata refresh and cleanup on unmount. Inspect actual slot mounting and native control behavior in a separately coordinated exact-source Dev packet after review; no install/reload/fixture mutation is authorized by this document. Use an explicitly approved safe fixture and preserve human bots, homes, histories, native Stop and queues.

If richer runtime status is later useful, establish the smallest watched metadata read and lifecycle invalidation using public contracts, with no output capture or provider wake. Verify the runtime supports any newly used watched-read method before enabling it; a newer build pin is not that proof. Do not create a scheduler, persistent subscription engine or custom Git cache in this exploration.

The prototype uses the supplied pane thread ID for Info/card and the originating composer scope for the action. New-thread and queued-message scopes are excluded; foreign, unknown or failed ownership reads render nothing. Metadata follows the existing keyed `ownership` RPC and `bots` invalidation, with no extra producer, transcript read, native status reconstruction or Git watch. Harness checks retain draft/attachment/selection, exercise a late response after scope change, refresh a renamed owner and hide a removed owner. The context-card host owns placement and native experiment selection; this change does not enable that experiment.

The BB-convention/settings correction merged in PR160 as `1a9a8b1`: host title/header/actions and distinct collection/create/overview/settings routes with registry controls. Settings→Bots and per-bot header/native entries expose identity, SOUL and future execution defaults. PR168 adds deliberate initial existing-board selection. PR169's worker overview already reuses native cached titles/status/draft/row-status hooks for persisted mapped IDs. PR170 adds the fixed native Bot records tab and Info action. Slots provide placement; they neither keep a provider running nor prove queue/process/Stop state. Git's environment-keyed public RPC and native watched invalidation remain the owner of Git freshness; Bots adds no poller, Git cache or duplicated Git panel. A bot home outside a repository may be not applicable rather than clean.

The test-only `tests/composer-selection-experiment.test.tsx` composes an unregistered selection probe alongside the actual registered Bot settings action. Eight cases exercise one deliberate same-provider model patch, one shared ownership lookup, preservation of structured mentions/attachments and omitted picker fields, missing-ownership/cross-provider/new/queued/foreign exclusions, running/submitting restrictions and unmount cleanup. The normal app still registers only Bot settings; it gains no setter control, removal policy or extra producer. The public SDK132/140 declarations expose the same setter and describe native same-provider versus provider-handoff behavior; the tests run against the repository pin only.

**Evidence limit:** the public app harness merges accepted selection fields and returns that snapshot. It has no native picker catalog, machine permission ceiling, fifteen-second settlement wait, provider handoff, Stop control or queue pipeline. Fictional fixture model names are intentional. Passing tests prove scoped hook composition and call/draft preservation in that model; they do not establish model availability, native reconciliation, atomic protection from a simultaneous provider change, or absence of native effects. No runtime control should be lifted from the probe as a production policy.

Keep native model/permission controls available. Own additive Bots contributions can disappear for absent/failed ownership; no inspected public customization option hides the host's model picker. Do not substitute CSS/DOM/private imports or a replacement composer. A permanent model-choice policy has not been selected.
