# Public capability verification

Date: 2026-11-10. Task: BOTS-3. Matt explicitly released the builder with “Ok go.” in `thr_898bvuxcfi`. This report records declaration checks and bounded runtime probes before BOTS-4 scaffolding. There is no Bots package or production bot yet.

## Decision and remaining gate

For Codex, use native compaction first and verified in-thread clear/re-brief when necessary. A successor thread is not required for the tested same-provider path. This does not establish cross-provider support or complete continuity: checkpoints, commitments, worker routing, concurrent inputs, drafts, and restart recovery remain implementation acceptance tests.

**The automatic-continuity coexistence gate remains open.** In the isolated host, a direct public `threads.compact` call returned `{ ok: true }` without reaching a registered `message.dispatch` hook that was set to record and reject every dispatch. An earlier initial spawn demonstrably waited on that hook. The installed Auto Compact plugin calls `threads.compact` from idle and failed handlers without checking manual-stop evidence. Bots therefore cannot assume its dispatch guard governs those compaction turns. Do not claim coexistence with that behavior or enable an automatic path on that assumption. See [the focused SDK request](sdk-continuity-gates.md).

The capability investigation is not complete while that critical path is unresolved. BOTS-4 remains behind BOTS-3. No core changes, sibling-plugin fixes, production compaction, or reconfiguration of installed user plugins were performed.

Production plugin inventory, settings and read-only RPC checks were made against the original instance without mutations.

The temporary probe package lived outside the repository at `bots-capabilities/probe` in this thread's storage. It registered no idle listener, schedule, automatic retry, or external messaging. The non-Git test home and host project existed only in that isolated instance. No user repository or production conversation was compacted, cleared, stopped or archived. The test threads were stopped and archived, the isolated instance was shut down, and neither test port remained listening.

Five manually controlled scenarios used Codex only: initial construction → compact → clear/pickup (three dispatched turns); active Stop (one interrupted turn); exploratory compaction admission (three dispatched turns); sustained admission verification (one short pickup and one compact turn); and fresh-session instruction binding (one short turn). This was ten requested turns in total, with no more than three in a scenario. A held pre-start thread executed zero model turns. Waits were bounded to 30 seconds; an explicit stop released the runtimes. The SDK has no verified hard token or monetary cap for these requests. Usage was recorded rather than converting tokens to an invented dollar cost; native compaction's accounting cannot be inferred from its zero output fields.

The first admission check read its counter immediately after API acceptance, which could have missed deferred dispatch. The final check kept the record-and-reject flag enabled from event sequence 104 until the new `turn/completed` event at sequence 113. The turn completed while that flag was still enabled and the hook recorded zero dispatches. This sustained check is the evidence for the admission gap; the immediate check alone is insufficient. A negative control armed the same guard and made an ordinary `threads.send` request: it received HTTP 409, logged the dispatch, and started no provider turn. The ordinary-send control also confirmed plugin-origin attribution, unlike the native compact request.

Durable evidence in the same thread-storage directory includes the probe source and `01-before-compact.json`, `02-after-compact.json`, `03-after-clear.json`, sanitized `04-history-after-clear.json`, `05-after-pickup.json`, `06-stopped-before-dispatch.json`, `07-transition-evidence.json`, `08-active-stop.json`, exploratory `09-compact-attribution.json`, definitive `10-sustained-compact-observation.json`, `11-final-transition-evidence.json`, `12-home-lifecycle.json`, `13-send-negative-control.json`, `14-unprompted-soul-marker.json`, and `provider-retry-consent-schema.json`.
